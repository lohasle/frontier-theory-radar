## 4. 今日深挖论文

- **一句话本质：** Context Cache 把 RAG 推理中重复出现的上下文块（系统提示、共享文档）压缩后缓存复用，让后续相似查询跳过重复的 KV-cache 计算。
- **底层问题：** 长上下文模型的 attention 计算是 O(n²)，在多用户共享文档集的 RAG 场景下，同一个文档会被反复编码，造成巨大浪费。
- **新命题 / 新方法 / 新证据：** 语义分块 → 语义嵌入 → 跨查询缓存命中 → 2.7x 延迟降低 / 60% KV-cache 节省 / 97% 精度保持。有代码，有 vLLM/SGLang 集成。
- **研究位置：** 工程优化型论文，建立在现有 long-context 和 KV-cache 研究基础上，创新在系统设计而非理论突破。
- **工程可验证性：** 有明确代码入口（github.com/zhihao-zhang/context-cache），兼容 vLLM/SGLang，可安排本周最小实验。
- **趋势关联：** 与 Speculative Retrieval（本次另一篇论文）互补——一个优化缓存复用，一个优化检索预取，共同指向 RAG 系统性能工程趋势。
- **长尾价值：** 语义分块 + 跨查询缓存的架构模式可迁移到其他推理加速场景（如多轮对话、批量推理）。
- **启发：** 推理优化的思路不限于模型内部（量化/蒸馏/投机解码），系统层面的缓存和预取同样重要。
- **行动建议：** 今天 clone 代码 + 跑基线测试，本周完成 vLLM 集成评估。
