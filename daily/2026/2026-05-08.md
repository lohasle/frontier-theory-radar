## 4. 今日深挖论文

- **一句话本质：** Agent 的上下文管理应从'统一保留/截断'转向'按相关性分粒度维护'。
- **底层问题：** 长时序搜索 Agent 在推理、工具调用、观察循环中产生大量中间内容，naive 累积导致上下文爆炸、成本增加、错误率上升。
- **新命题 / 新方法 / 新证据：** Context-ReAct 将 Agent 轨迹分为不同粒度级别（全保留→摘要→丢弃），按当前任务相关性动态调整。这是 ReAct 模式的重要扩展。
- **研究位置：** 源头论文。首次将弹性上下文编排作为 Agent 系统的核心设计问题提出。
- **工程可验证性：** 框架可集成到任何基于 ReAct 的 Agent 系统中。最小验证：在现有 Agent 中增加上下文分段摘要逻辑，对比固定窗口截断的基线。
- **趋势关联：** 与 MemGPT、Lettre 等记忆管理方案互补；属于 Agent 基础设施层的关键进展。
- **长尾价值：** 线性联想记忆的精确容量阈值（d²≍n log n vs d²≍n）是 RAG 向量库设计的量化依据。
- **启发：** 在设计任何长任务 Agent 时，应将上下文管理视为与工具使用同等重要的核心能力。
- **行动建议：** 今天读 Context-ReAct 方法论，在现有 Agent 中实验上下文分段策略。
