## 4. 今日深挖论文

- **一句话本质：** 它不是再优化一个 prefix-cache，而是定义了一种‘比 KV cache 更完整的执行态对象’，让端侧 agent 能像进程一样被 checkpoint/restore。
- **底层问题：** 高吞吐高并发的云上 LLM serving 与低延迟小批量端侧 physical-AI serving 的状态管理需求根本不同——后者要频繁分支、回退、中断、重入，单靠 KV cache 无法表达完整执行态。
- **新命题 / 新方法 / 新证据：** 新命题是‘执行态应被建模为图绑定的胶囊（capsule）而非单一 KV 片段’；方法是用 graph-bound 结构记录可恢复的执行状态；证据来自面向低延迟端侧场景的设计分析，外部代码与 benchmark 暂无。
- **研究位置：** 介于系统设计与工程方法论之间，价值不只在性能数字，更在‘把 agent serving 的状态抽象提升一个层级’这一思想。
- **工程可验证性：** 可在现有本地 serving runtime 上做替代 PoC：对一段需要分支/复位/重入的 agent 轨迹，分别用 KV-cache 回滚与执行态胶囊恢复，比较端到端延迟、内存占用与状态一致性。
- **趋势关联：** 与 on-device AI、interactive agent、robotics policy、physical-AI 四条趋势交汇，值得纳入未来 1-3 个月重点跟踪。
- **长尾价值：** 即便短期无开源，‘执行态是一等公民’的思想也可沉淀为端侧 serving 架构 checklist。
- **启发：** 很多 serving 优化假设的是‘长前缀、高并发’，但真实 agent 负载更像‘短上下文、高频分支’，状态模型要据此重设。
- **行动建议：** 今天先产出一页执行态胶囊 PoC 设计：恢复目标、对照组、延迟/内存/一致性指标、失败阈值。
