## 7. 启发

### Agent 动态环境评估
- EvoArena 揭示：当前 Agent 在环境变化后的知识过期检测和行为自适应是系统性弱点。
- 生产部署中，环境变化（API 变更、依赖升级）导致的 Agent 故障远多于任务本身的复杂性导致的故障。

### Agent 知识工程
- Agents-K1 将科研论文从'文档'提升为'知识图谱'，包含实体、因果机制和方法演化。
- 当前研究 Agent 将论文简化为摘要+扁平引用边的做法，丢失了科学推理所需的核心信息。

### Agent 工具架构
- HyperTool 的核心洞察：局部确定性的工具工作流不应暴露在模型推理轨迹中。
- MCP 风格的统一工具接口将模型从低层数据流管理中释放，专注高层规划。
- 执行粒度不匹配是当前工具增强 Agent 的普遍架构问题。

### AI4Science 范式
- EurekAgent 提出：当模型能力足够强时，瓶颈从工作流设计转向环境设计。
- 环境工程包括资源设计、约束设计和接口设计，决定 Agent 能发现什么。

### 检索范式演进
- RA-RFT 将检索标准从语义相似性改为推理结构同构性——从'找相似文本'到'找相似推理模式'。
- 这一范式转变对数学推理、代码生成等需要深层类比的任务有重要意义。

### 个人学习启发
- 今天 5 篇核心论文共同指向一个趋势：Agent 工程正在从功能实现走向鲁棒性与自适应。
- 优先关注直接工程价值：EvoArena（评估）> HyperTool（架构）> Agents-K1（知识）> EurekAgent（范式）> RA-RFT（理论）。
